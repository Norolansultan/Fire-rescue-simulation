# ARCHIVE — superseded design documents

Historical record only. **Do not build from anything in this directory.**

Everything here is replaced by `/SPEC`. These files contain design decisions that
were later reversed, and a builder who reads them will implement the wrong system:

- Cycle counts of **eight** or **nine** (the design is twenty)
- A **two-scenario** structure with a cross-scenario transfer test (there is one scenario)
- **Two sittings** (there is one continuous session)
- The condition name **`human`** (it is `directed`, and the responder is automated)
- A **four-region** UI layout (superseded by map + status strip + report rail + two drawers)
- A **two-class** atom corpus (superseded by the four-tier model)
- A **six-cell** Paper 2 design (guidance mode is nested inside condition, not crossed)

Kept because the reasoning is worth having: `12_Consistency_Audit_and_Open_Design.md`
records how the conflicts were found, and `04_Reconciliation_and_Feasibility.md` records
the authoring-cost analysis that forced the volume revisions.

`PhD_Literature_Framework.md` is not superseded — it is the literature chapter's
theoretical architecture and remains current. It stays at the top level.
